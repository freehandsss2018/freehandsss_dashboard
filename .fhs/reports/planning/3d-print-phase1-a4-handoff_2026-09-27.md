## 3. 現行人手流程 → 自動化目標（Fat Mo 2026-07-10 親述，【Fat Mo 裁決】，勿再問）

1. **3D 掃描**客人的白色石膏倒模 → 得 OBJ。掃描器只掃到外形／姿態，**掃不到指甲與細紋理**。
2. 對石膏實物 **360° 多角度拍照**（`IMG_*.JPG`，與 OBJ 同資料夾）——用途是師傅補刻紋理時的**對照參考**。實測：石膏實物的指甲本身也很淺，師傅畫出來的清晰指甲是「對相腦補創作」。
3. OBJ＋相片交**師傅**（ZBrush，`.ztl` 工作檔在客名資料夾）：補／誇張化易識別紋理。標準＝**易識別即可，不必 100% 真實**（縮到 30mm 後細節本來就顯示不出）。
4. 按訂單**刻字**（縮寫＋日期）刻入模型。
5. 完成檔交廠家打印。

**自動化目標**：用 Blender 腳本取代步驟 3–4 的大部分人手。
**2026-07-12 降級裁決（【Fat Mo 裁決】）**：AI 紋理與師傅手工仍有距離（AI 版偏腫、師傅版線條幼細）→ **紋理繼續由師傅做；v0 實用範圍＝AI 只負責縮放＋刻字＋加環＋QC＋出檔**。

## 4. 師傅完整工序與成品規格（已由 A3 用 Blender 視覺對比樣本解密，【已證】）

師傅版成品（稱 Level3）相對原掃描（稱 Level0）做了：
1. **裁切**：腳踝處平切成一個橢圓平面。
2. **重擺姿**：腳趾向下垂吊、切面向上。
3. **切面凹刻**客人縮寫＋日期（刻在平面上，故機械化容易）。
4. **頂部加一體成型掛環**（成品島嶼數＝1，不是廠家事後加）。
5. **誇張化摺痕／趾甲**（藝術活，唯一不機械化的部分）。
6. 細分（約 28 萬 → 110 萬面）→ **縮放至規格** → 按命名規格出檔。

**成品規格（【已證】，13/13 樣本 STL 用 numpy 解析驗證）**：
- 檔名尺寸＝mesh **最長軸（永遠是 Y 軸）**的長度，分毫不差。
- 命名規格：`<客名>-<部位>-<尺寸>mm-x<數量>.stl`。
- **腳＝30.5mm 固定**（Fat Mo 確認）。**手＝隨姿態變化、無公式**，由 Fat Mo 逐單標在檔名，pipeline 只讀檔名，**禁自行推算**。
- **掛環＝固定標準件**：`3d/input/Ring-24545.obj`，實測 2.0×4.5×4.5mm（檔名即尺寸），水密；原檔座標有偏移須重置中。只准擺位＋boolean union，**禁自造、禁縮放環**。
- 原掃描已水密；師傅版反而有少量 boundary／non-manifold 邊（ZBrush 匯出殘留），廠家軟件容忍。所以修復重點**不是補洞**。

## 6. 已驗證事實與技術地雷（【已證】，不必重查）

- 環境：Blender **5.1.1**＋MCP addon（port 9876，須 Blender 開著才連得到）。1.1M 面 mesh 一律用 `foreach_get/set`＋numpy，禁 Python 逐點 loop。
- Level3 STL 帶非標準 `COLOR=`／`MATERIAL=` header，令 Blender 內建 STL importer **靜默失敗（0 verts）**，須自寫 numpy parser（腳本已有 `import_binary_stl_numpy`）。
- 原掃描有 4,226 條退化碎邊，須先 `dissolve_degenerate(0.005mm)` 再做紋理，否則白斑＋趾甲被毀。
- 腳踝「燈芯絨」橫紋＝原掃描真實摺痕，不是 bug。
- 文字旋轉 Rx90° 會左右鏡像，須額外 X 翻轉；文字 cutter 須「扁平字＋Solidify」才水密；boolean 後會有浮空碎片，須保留最大連通元件。
- OBJ importer 有時把 axis convention 寫進 `matrix_world` 而非頂點座標，須在匯入後 bake 成 Identity（腳本 `bake_current_transform`）。
- Pilot 已證：自動 import→轉向→縮放→出檔，最長軸精確 30.50mm。
